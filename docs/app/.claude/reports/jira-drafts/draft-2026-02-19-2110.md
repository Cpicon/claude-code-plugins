**Summary:** Fix User Registration: Off-by-one error allows duplicate email registrations

**Description:**

## Background
During routine testing, it was discovered that users can register multiple accounts using the same email address. This violates the application's uniqueness constraint for email addresses and creates data integrity issues. Investigation revealed an off-by-one error in the duplicate email validation logic.

## Root Cause
**Primary Cause**: The email duplicate check uses an incorrect range-based loop with an off-by-one error.
- **Evidence**: `main.py:75-84` - Loop uses `range(0, user_id_counter)` but user IDs are 1-indexed
- **Technical Details**:
  - User IDs start at 1 (counter incremented before use at `main.py:86`)
  - Range starts at 0 (where no user exists) and excludes upper bound
  - Most recently created user is always skipped in the check
- **Contributing Factors**: Inconsistent validation patterns - username check uses `.values()` iteration (lines 71-73) which works correctly, while email check uses fragile index-based loop

## Impact
- **Direct Effects**: 100% of registration flow affected - all users can register with duplicate emails
- **Risk Level**: HIGH
- **Affected Components**: User registration endpoint, data integrity layer
- **Security Implications**: Privacy risk - multiple accounts with same email could lead to information disclosure

## Implementation Plan

### Recommended Approach: Proper Fix
**Rationale**: Replace the fragile index-based email check with `.values()` iteration to match the working username check pattern. This provides consistency and eliminates the indexing issue.

### Steps
1. **Replace email validation logic** - `main.py:75-84`
   - Change: Replace range-based loop with `.values()` iteration
   - Reason: Eliminates off-by-one error and matches working username validation pattern

   - Change: Add 6 test cases for duplicate email scenarios
   - Reason: Ensures fix works and prevents regression
